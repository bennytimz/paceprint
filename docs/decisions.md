- **2026-11-21 21:57 — Breathing-trace talking detector: rejected, not adopted.** The SDK talking flag can't tell silence from speech on the owner's setup (talk contrast: silent 64 %, reading aloud 96 %, silent again 96 %). We tested whether the chest trace could detect talking instead, offline, on two recordings: the talk contrast (20 s reading between silent parts) and the talk check (silent throughout, 5/min, nose) as a control (`scripts/eval-talk-detector.ts`, 4 s windows, 2 s trimmed at each part change). Measures: chest-trace energy at 1–4 Hz, as a share of window power and as an absolute level. Adoption rule, set before testing: clear separation of reading from silence on **both** recordings, and no dependence on pacing quality.
  - **Share of 1–4 Hz power:** best threshold, tuned on these same windows (so optimistic), catches 92 % of reading windows; false alarms 0 % of contrast silence but 7 % of the silent talk check. On the silent paced windows it correlates +0.34 with the local follow score and −0.29 with breath size (n = 52). Fails both conditions.
  - **Absolute 1–4 Hz level:** false alarms on 25 % of the silent talk check; correlates +0.75 with breath size and −0.48 with follow score. Fails both, and is the circular case: it mostly measures how the person breathes.
  - **Why circularity rules it out:** coupling is computed from the same breathing traces. A talking refusal that depends on breath size or pacing quality removes some paces' data more than others for reasons unrelated to talking, and the comparison between paces would no longer be fair. Any future detector must show no relationship with follow score or breath size on silent paced data before it is used.
  - No threshold changed, no coupling result looked at. Rule 8 still needs a working talking detector; next candidates are mouth movement from the face points (needs a recording change the owner approves) and asking Presage about the flag.
- **2026-11-21 22:09 — Mouth-opening talking detector: test fixed before data.** Candidate for Rule 8's talking check, since the SDK flag is uninformative and the breathing-trace detector was rejected. Code: `src/core/mouth.ts`; test: `scripts/eval-mouth-detector.ts`, written and dry-run on synthetic recordings before any real mouth data existed.
  - **Measure.** Per face-mesh frame, one number: lip-opening ratio = distance(inner upper lip 13, inner lower lip 14) / distance(mouth corners 61, 291). Nothing else from the face points is kept. Speech score = RMS of that ratio in the 2–7 Hz articulation band over a 2 s window (1 s padding, unscored if the ratio is missing for more than 0.25 s). Breathing, even through the mouth at 5/min, moves the lips below 0.5 Hz, outside the band.
  - **Data.** One `npm run mouth-contrast` run (owner): 20 s silent, 20 s reading aloud, 20 s silent, then 60 s silent at 5/min (30 s nose, 30 s mouth). Windows 2 s every 0.5 s, 2 s trimmed at each part change.
  - **Threshold.** From the first silent part and the reading only: geometric mean of silent-1's 95th percentile and reading's 10th percentile (requires reading p10 > silent-1 p95). The other three parts are held out.
  - **Adopt only if all hold:** ratio available ≥ 90 % of the time in every part; ≥ 90 % of reading windows at or above threshold; ≤ 5 % false alarms in each held-out silent part (silent-2, 5/min nose, 5/min mouth); and headroom: in each silent paced part, the 95th percentile score ≤ half the threshold.
  - **How it avoids circularity.** The score only sees 2–7 Hz lip movement, so breath depth and pacing quality are outside what it measures (tested: big slow mouth opening and irregular slow breathing score < 1/10 of speech, and that test fails if the band is widened to include breathing). The pass rule then checks refusals directly on silent paced breathing, nose and mouth: almost none, with a 2× margin, so no amount of good or poor pacing comes near triggering one. A correlation pass rule (|r| ≤ 0.2 vs follow score and breath size) was considered and dropped during the synthetic dry run: on overlapping windows a detector with no link to breathing failed it by chance (|r| 0.51). Correlations are still printed for information. A synthetic detector whose lip movement grows with breath depth is rejected by the test.
  - **If adopted:** talking = speech score ≥ the threshold printed by the test, written here with its number before any coupling result is looked at; held 2 s (existing talking hold, unchanged); it replaces the SDK talking flag as the talking check (the flag stays in recordings for reference); a missing lip ratio counts as untrustworthy. If rejected: logged here, and Rule 8 still has no working talking check.
  - **Limits.** One person, one setup, one run. The face-mesh index layout is inferred: the SDK does not document it, but 478 points and the points we checked match the standard face-mesh-with-iris layout. Wrong indices would show up as no separation while reading.
  - **Privacy.** Only the ratio is computed and saved (owner's test recording). App recordings drop it until the consent text says so (pending owner approval, NEEDS_OWNER.md). Raw test dumps keep only the count of face points (no coordinates) and no expression scores.
  - No threshold changed.

- **2026-11-21 23:19 — Burst tolerance: rule fixed before test.** Rule 8 stays (talking is refused); this changes how the SDK talking flag is turned into "talking". Code: `src/core/talking.ts`; test: `scripts/eval-burst-tolerance.ts`. Committed before any test was run.
  - **Problem, from talking-flag data only.** Today every flagged packet starts the 2 s talking hold, and when the hold ends the 2 s settle follows, so one 0.1 s blip refuses about 4 s. Blips about a second apart therefore chain into a near-total refusal: talk check 2 (23:13, silent) flagged 21 % of packets in 52 blips of at most 2.0 s, and only 2.2 of 60 s survived.
  - **Rule.** Talking = the SDK flag was on for at least 3 of the last 4 s (each packet's flag lasts until the next packet, at most 0.5 s, so a data gap never counts as talking). While that holds, and for the existing 2 s talking hold after it, data is refused; the 2 s settle is unchanged. Single blips, and blips covering a minority of the time, no longer refuse anything on their own.
  - **Why these numbers.** Speech is sustained: the flag was on 96 % (talk contrast 21:53) and 100 % (mouth contrast) of the reading parts, so reading fills a 4 s window. Requiring 3 of 4 s leaves room for pauses between sentences (up to 1 s per 4 s) and cannot be met by any single blip up to 3 s. The numbers come from the reading parts. Disclosure: before writing this I had already seen talk check 2's flag summary (21 %, blips ≤ 2.0 s), which is the control below; the rule was not tuned to it, and no window or fraction was tried on it.
  - **Test (held out).** Reading: a new `npm run talk-contrast` run in the same clean setup (the owner's next run). Silent control: the 5/min part of talk check 2 (recordings/talkcheck-2026-11-21T22-14-31-388Z). 2 s windows every 1 s, 2 s trimmed at each part change; a window counts as refused when the talking refusal (rule plus 2 s hold) covers at least half of it. **Adopt only if** at least 90 % of reading windows are refused **and** at most 5 % of silent control windows are refused. Nothing is tuned after seeing the result; if it fails it is not adopted and the owner is told. The contrast run's silent parts are reported for information only.
  - **If adopted:** the sustained rule replaces per-packet talking in validity, logged here before any coupling result is looked at. No other threshold changes.
